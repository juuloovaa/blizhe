# Ближе — UX-структура MVP

## Контекст запуска

1. Пользователь открывает Telegram-бота.
2. Нажимает кнопку **Открыть приложение** (Web App).
3. Mini App загружается в Telegram WebView с `initData`.
4. Сервер проверяет подпись `initData` и создаёт/обновляет профиль.
5. При первом входе — онбординг (режим + опционально имя/местоимения).

## Принципы UX

- Один экран — одна задача.
- Мобильный Telegram WebView first (узкая колонка, крупные тап-зоны).
- Тема Telegram (`bg_color`, `text_color`, `button_color`) + фирменный акцент приложения.
- Личное и парное визуально разделены, но не перегружены.
- Нет онлайн-статуса, геолокации, ленты активности.
- Деликатный тон: поддержка, без диагнозов и категоричных оценок.

## Пользовательские сценарии

### A. Первый запуск (соло)

`Splash / Auth` → `Онбординг: режим` → `Онбординг: профиль` → `Главная`

### B. Приглашение партнёра

`Профиль / Пара` → `Пригласить` → share deep link → партнёр открывает `?start=invite_CODE` → `Подтверждение пары` → оба видят статус «В паре»

### C. Вопрос дня (пара)

`Главная` → вопрос для пары → ответ → ожидание партнёра → оба ответили → раскрытие ответов

### D. Заметка о настроении

`Главная` → выбрать настроение → опциональная заметка → сохранить → бот уведомляет партнёра → deep link в Mini App

### E. Карточка

`Карточки` → категория → вытянуть → сохранить / отправить партнёру

### F. Тест

`Тесты` → выбрать → отвечать → (совместный: ждать партнёра) → результат с совпадениями и вопросами для обсуждения

### G. Помощник

`Помощник` → приватный чат с маскотом → подсказки / свободный текст → safety redirect при кризисе

## Информационная архитектура

```
Ближе
├── Онбординг
│   ├── Режим (один / пара)
│   └── Профиль (имя, местоимения)
├── Главная
│   ├── Вопрос дня
│   ├── Настроение и заметка
│   └── Приглашения в тесты
├── Карточки
│   ├── Категории
│   ├── Карточка дня / случайная
│   └── Избранное
├── Тесты
│   ├── Личные
│   ├── Совместные
│   ├── Игровые
│   └── Результат / прогресс
├── Помощник
│   └── Приватный чат

```

## Telegram Web Apps API

| API | Использование |
|-----|----------------|
| `themeParams` | CSS-переменные темы |
| `BackButton` | Вложенные экраны (результат теста, карточка, настройки) |
| `MainButton` | Основные действия: «Сохранить», «Отправить», «Подтвердить пару» |
| `HapticFeedback` | Ответ, сохранение карточки, завершение теста |
| `expand` / fullscreen | При открытии приложения |
| `openTelegramLink` / share | Отправка invite-ссылки |
| `CloudStorage` | Не в MVP (сервер — источник истины) |

## Состояния пустых экранов

- Нет пары: мягкий CTA «Пригласить партнёра», личные фичи доступны.
- Нет ответа партнёра: «Ответ откроется, когда вы оба ответите».
- Нет избранных карточек: подсказка вытянуть первую.
- Помощник пустой: 3–4 стартовых промпта.

## Safety (помощник)

При маркерах самоповреждения / насилия / угрозы жизни:

1. Остановить «обычные» советы.
2. Показать карточку экстренной помощи.
3. Предложить обратиться к близким / специалистам / экстренным службам.
4. Не ставить диагнозы.
